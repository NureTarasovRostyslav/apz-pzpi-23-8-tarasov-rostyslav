3 ОПИС ВИКОНАНОЇ РОБОТИ
      3.1 Загальні відомості про систему Git
      Git – це розподілена система контролю версій, розроблена Лінусом Торвальдсом у 2005 році. На відміну від централізованих систем (як-от SVN), Git надає кожному розробнику повну копію історії проекту, що забезпечує високу швидкість роботи та можливість автономного функціонування без підключення до сервера.
      3.2 Архітектурні принципи
      Основними архітектурними рішеннями Git є:
      * Контентно-адресоване сховище: дані ідентифікуються за їхнім змістом (хешем), а не за іменами файлів.
      * Модель знімків (Snapshots): замість зберігання різниць (deltas), Git зберігає стан всієї файлової системи в певний момент часу.
      * Незмінність даних: після запису в базу об'єкт не може бути змінений без зміни його ідентифікатора (SHA-1 хешу).
      
      3.3 Об'єктна модель даних
      В основі архітектури Git лежать три типи об'єктів:
      * Blob (Binary Large Object): зберігає лише вміст файлу. Метадані (права доступу, назва) у блобі не зберігаються.
      * Tree: представляє структуру каталогів. Містить імена файлів та посилання на відповідні блоби або інші об'єкти Tree.
      * Commit: містить посилання на дерево верхнього рівня, метадані (автор, дата, опис) та посилання на батьківські комміти, що формує граф історії.

      3.4 Механізми цілісності та оптимізації
      Для ідентифікації використовується алгоритм SHA-1. Кожен об'єкт отримує унікальний 160-бітний ключ. Це гарантує, що будь-яка зміна навіть одного біта в коді призведе до повної зміни хешу комміту.
      Оптимізація місця досягається через "Pack-файли". Коли об'єктів стає забагато, Git групує їх, використовуючи дельта-компресію (зберігаючи лише відмінності між схожими версіями файлів), що значно економить дисковий простір.
